# Peers: parallel sessions in one checkout

Date: 2026-10-25. Status: built, tested, installed 0.3.0 at user scope.

## Problem

William runs about five Claude Code sessions at once. Worktrees cost a merge per session and an install per worktree. One shared tree costs chatter: every session sees peer edits in `git status` and spends messages on "I will ignore that". Order of optimization: time first, then tokens.

## Target

A session behaves like a person on a shared document. It edits its own files. It sees a peer's cursor only on the file it is about to touch. It commits its own files. Tickets update themselves from what the session did.

## Shape

One Claude Code mod (`hooks/register.tsx`) and one CLI (`bin/peers.mjs`), one repo, installed with `/plugin install`.

| Part | Event | Cost |
|---|---|---|
| Ledger | `tool.call` on Edit, Write, NotebookEdit; Bash by dirty-file mtime snapshot before and after | host side, no tokens |
| Awareness | `tool.call` on Read and the edit tools: one `context` line when a peer touched that file since this session last read it | ~30 tokens, only on hit |
| Band | `ui.render` AbovePrompt from an atom refreshed every 3 s | none |
| Rule | `prompt.compose` adds one section | ~70 tokens per request, cached |
| Guard | Bash staging, discards, branch switches and writing formatters denied when they reach a peer's uncommitted file (`lib/guard.mjs`); Write denied when it drops a peer's uncommitted lines | none |
| Scoped git | `peers status|diff|commit|check` | one command each |
| Tasks | `peers ready|claim|close` on Backlog.md; commit appends the sha to the task notes | one command each |

Ledger: `~/.claude/peers/<encodeURIComponent(root)>/<session>.json`. One writer per file, so no locks.

Agent-neutral core (0.8.0). `lib/core.mjs` holds the ledger, the Bash snapshot, the guard and the Write deny over a small io (read, write, list, stat, run, now). The mod binds it to `$` per call; `lib/io.mjs` binds it to node. `lib/agents/{codex,cursor}.mjs` map each agent's hook JSON to one event shape and back. `lib/hook.mjs` runs one event per process; the snapshot waits in `~/.claude/peers-run/snap/` for the post event.

## Decisions

- Hunk-level attribution (2026-10-26, William: the four gaps are core, not convenience). Each edit records the distinctive lines it added and removed. `peers commit` keeps a peer's hunks out of the commit.
- A private index from HEAD plus `commit-tree` and a compare-and-swap `update-ref`. The 10-06 lesson (`-U0` patches with dropped hunks shifted lines) is why the blob is built in code from the base text, never with `git apply --unidiff-zero`.
- Claude Code's Write already refuses a file changed since the last Read. The mod's Write deny covers the rest: a fresh Read, then a whole-file Write that loses a peer's lines.
- `peers check` uses `~/worktrees/<repo>-check`, never the push worktree.
- Board: Backlog.md (2026-10-25, replaced beads): plain Markdown, git history, GitHub audit without a shell. The agent never edits status itself. `peers` does.
- No MCP, no server. Hooks and a CLI only.
- Board adapter (2026-10-27, 0.16.0): one interface (`ready`, `claim`, `note`, `open`, `close`), one adapter per tracker, picked by `board` in the config. Against shell templates in the config (fragile quoting on Windows). Jira by acli (default, uses the user's own login, no token in peers) or REST.
- Action log and outbox (2026-10-27, 0.16.4). Options: A keep direct board calls (lost notes, no trace); B an append-only action log per session with board writes as pending sends, retried on the next command; C event-source the whole ledger (every edit an event; rewrites the core, and the edit hook fires on every write). Ranked: no lost board writes, a readable trace, no change to hunk ownership. Chose B. Claim stays direct (it must fail loud); close's status move must land or the ticket stays bound.
- Storage local only (2026-10-27, William: 10-20 GB is fine). The ledger holds code lines from work repos, is written on every edit and means nothing on another machine. Heavy use is about 1 GB a year, so no pruning yet. A cloud export, if ever, is opt-in and carries no code.

## Tested (2026-10-25)

- Edit, Write and Bash (`sed`) attribution. Read and Edit awareness lines, also when the Edit lands on a file a peer changed since the read. Prompt rule delivered. Guard denies whole-tree staging only when a peer's file is dirty in that repo, and only for git at a command position. `peers status|commit|ls|check` (wren gate passes in `~/worktrees/wren-check`). Hook latency about 70 ms.
- The band was not seen rendering: every test peer exits cleanly and marks itself ended. William checks it with a seeded live ledger.

## Tested (2026-10-26, 0.3.0)

- `lib/guard.test.mjs`: 53 commands, staging, discards, switches, formatters, prose.
- Two sessions, one file: A's commit holds only A's hunk; B's lines stay dirty; B's commit holds only B's. A peer's staged file stays out. A mixed hunk and a no-newline file commit whole, with a note.

## Tested (2026-10-26, 0.8.0)

- Claude Code parity: one headless `claude -p` run on the old mod and on the new one (Edit, a Bash append to a dirty and a clean file, `git add -A`). Same ledgers, plus one gain: the Bash line in the file that was dirty before now records (the old cache lost the old text).
- `lib/core.test.mjs`: 29 checks on a real repo, the Claude path and the Codex and Cursor hooks.
- Live on cursor-agent 2026.09.18 with `--project` hooks: shell and Write lines recorded, session ended, `peers status` in its shell finds its session. Cursor runs tools in parallel; snapshots are per tool use.
- Codex: fixtures from its hook docs only. Gemini CLI dropped (replaced by Antigravity on 2026-06-18).

## Open

- Hot reload across a `/clear`: no `session.start` fires, the ledger file is created on the first edit.
- `peers check` on wren needs a one-time `pnpm install` in the check worktree (22 s).
- A session that dies without `session.end` looks live for 12 hours and keeps the guard on for that repo.
- Sessions open before the install load the mod only after a restart. Edits made before that are unattributed.
